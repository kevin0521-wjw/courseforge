## 三、CourseForge 的差异化定位

一句话：**别人做「一个平台上的一个 App」，CourseForge 做「一份零依赖、数据在自己手里的课表」**。

1. **同一份代码，三端可用**——`web/` 是纯静态站，浏览器打开即用；桌面端只是套了层 Electron 壳复用同一份页面；手机浏览器打开同一链接即是 App（可添加到主屏幕）。竞品几乎没有同时覆盖三端的。
2. **导入方式最全**——照片 OCR、PDF、粘贴文本三条路都通，竞品普遍只做「教务直连」或「手工录入」，教务接口一变就失效。
3. **数据完全在用户手里**——无账号、无服务器、无遥测；换设备靠一个 JSON 文件迁移。校园小程序类竞品的数据在第三方服务器。
4. **零外部依赖**——不引 CDN、不引框架、不引字体、不引图表库，`dist/CourseForge-standalone.html` 单文件双击即用，断网也能跑。这一点所有竞品都做不到（APP 要有构建产物，小程序要有平台）。
5. **自带 182 项自动化测试**——课表类是「一次配置管一学期」的软件，正确性比功能数量重要。

## 四、本轮（v0.3）依据对比补齐的缺口

对照上表逐项排查后，本轮补齐了 4 个高频缺口 + 2 个实测缺陷：

| # | 缺口 | 对标竞品 | 落地情况 |
| --- | --- | --- | --- |
| 1 | **深色模式** | 拾光课程表、sleepy、ClassIsland 均有 | 三态主题（跟随系统/浅色/深色），首屏前应用避免闪白，`localStorage` 持久化；8 种课程色各配深色变量 |
| 2 | **.ics 日历导出** | ZJU-Calendar-Maker 的核心能力 | 按周展开为独立 VEVENT（兼容 iOS/安卓/Google/Outlook），浮动时间免 VTIMEZONE 坑，含 10 分钟提醒，严格 RFC 5545 折行 |
| 3 | **当前节次进度 + 下一节倒计时** | ClassIsland 的提醒能力 | 今日课程区实时进度条、剩余时间、下一节开课倒计时，每分钟自动刷新，页面隐藏时暂停省电 |
| 4 | **PWA** | 拾光课程表/sleepy 的原生体验 | `manifest.webmanifest` + Service Worker 离线缓存 + 图标；`file://` 环境静默跳过 |
| 5 | **打印课表** | ClassIsland 的大屏展示 | A4 横向打印样式，隐藏全部交互元素、保留课程配色、压缩行高塞进一页 |
| 6 | **显示周末开关** | 多数竞品支持 5 日视图 | 设置抽屉可关闭周末，网格/列表/统计/周次区间同步联动，并显式提示被折叠的周末课程数 |

### 实测中发现并修复的缺陷

| 缺陷 | 严重度 | 说明 |
| --- | --- | --- |
| **ICS 折行切碎 emoji** | 中 | `foldLine` 把高位代理算 2 字节、低位算 3 字节（实际应 4），导致可能从代理对中间折行。已按码点重写并加回归测试 |
| **移动端点击区不足 44px** | 高 | `.parity-bar .btn`(32px)、`.lr-actions .btn`(34px)、`.tool-actions .btn`(36px) 等复合选择器优先级高于通用 `.btn`，逐条覆盖后清零 |
| **移动端输入字号 <16px** | 高 | `#importText`(14px)、`.mode-select`(13px) 会让 iOS 聚焦时自动放大整页；ID/类选择器优先级高，需 `!important` 兜住 |
| **移动端工具栏中文竖排** | 中 | 7 个按钮挤一行导致「导入课表」逐字竖排；改为三列网格，危险操作「清空数据」独占一行 |
| **PWA 清单 MIME 错误** | 高 | 本地服务器未映射 `.webmanifest`，返回 `application/octet-stream`，浏览器会直接拒绝清单 |
| **showWeekend 兼容性** | 低 | 仅显式 `false` 才关闭周末，`undefined`/非法值一律按显示处理，保证旧备份文件可正常导入 |

### 多学期引入的两个隐性坑（已处理）

| 坑 | 说明 |
| --- | --- |
| **切换学期丢数据** | 课程与设置是「工作副本」，切走前必须先 `persist()` 回写当前学期，否则切一次就丢一次改动 |
| **改动只改内存不落盘** | 重命名曾漏写 `persist()`，导致界面已更新但 `localStorage` 未变、刷新即回滚。已加断言：`switch/create/rename/delete` 四个分支都必须落盘 |

## 七、明确的取舍（不做什么）

- **不做账号体系**：学生课表是私事，导出/导入 JSON 已够迁移，多一个账号就多一份泄露面。
- **不做云同步为默认**：与「数据在自己手里」的定位冲突，只作为 v1.0 的可选能力。
- **不做原生 App**：三端复用一份零依赖网页的收益远大于原生性能收益；PWA 已能覆盖「添加到主屏幕」的需求。
- **不做大文件/视频存储**：超出课表工具的边界。
- **不引任何前端框架**：一旦引入，单文件离线版就不复存在，这是本项目最核心的差异点。

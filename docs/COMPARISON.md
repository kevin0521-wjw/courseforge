## 三、CourseForge 的差异化定位

一句话：**别人做「一个平台上的一个 App」，CourseForge 做「一份零依赖、数据在自己手里的课表」**。

1. **同一份代码，三端可用**——`web/` 是纯静态站，浏览器打开即用；桌面端只是套了层 Electron 壳复用同一份页面；手机浏览器打开同一链接即是 App（可添加到主屏幕）。竞品几乎没有同时覆盖三端的。
2. **导入方式最全**——照片 OCR、PDF、粘贴文本三条路都通，竞品普遍只做「教务直连」或「手工录入」，教务接口一变就失效。
3. **数据完全在用户手里**——无账号、无服务器、无遥测；换设备靠一个 JSON 文件迁移。校园小程序类竞品的数据在第三方服务器。
4. **零外部依赖**——不引 CDN、不引框架、不引字体、不引图表库，`dist/CourseForge-standalone.html` 单文件双击即用，断网也能跑。这一点所有竞品都做不到（APP 要有构建产物，小程序要有平台）。
5. **自带 512 项自动化测试**——课表类是「一次配置管一学期」的软件，正确性比功能数量重要。

### 实测中发现并修复的缺陷

| 缺陷 | 严重度 | 说明 |
| --- | --- | --- |
| **ICS 折行切碎 emoji** | 中 | `foldLine` 把高位代理算 2 字节、低位算 3 字节（实际应 4），导致可能从代理对中间折行。已按码点重写并加回归测试 |
| **移动端点击区不足 44px** | 高 | `.parity-bar .btn`(32px)、`.lr-actions .btn`(34px)、`.tool-actions .btn`(36px) 等复合选择器优先级高于通用 `.btn`，逐条覆盖后清零 |
| **移动端输入字号 <16px** | 高 | `#importText`(14px)、`.mode-select`(13px) 会让 iOS 聚焦时自动放大整页；ID/类选择器优先级高，需 `!important` 兜住 |
| **移动端工具栏中文竖排** | 中 | 7 个按钮挤一行导致「导入课表」逐字竖排；改为三列网格，危险操作「清空数据」独占一行 |

| **showWeekend 兼容性** | 低 | 仅显式 `false` 才关闭周末，`undefined`/非法值一律按显示处理，保证旧备份文件可正常导入 |

### 多学期引入的两个隐性坑（已处理）

| 坑 | 说明 |
| --- | --- |
| **切换学期丢数据** | 课程与设置是「工作副本」，切走前必须先 `persist()` 回写当前学期，否则切一次就丢一次改动 |
| **改动只改内存不落盘** | 重命名曾漏写 `persist()`，导致界面已更新但 `localStorage` 未变、刷新即回滚。已加断言：`switch/create/rename/delete` 四个分支都必须落盘 |

### 教务直连落地时踩到的四个真问题（已处理）

| 问题 | 说明 |
| --- | --- |
| **表格单元格里的 `<br>` 被吞掉** | 逐标签累积文本时标签本身会被消费，不显式补 `\n` 就会把「课程名/教师/地点/周次」粘成 `高等数学张老师东区一教1011-16周`，启发式完全拆不开 |
| **rowspan 合并的课被解析成两门** | 合并单元格在矩阵里是同一个对象重复出现，按「位置」遍历就会重复计数；改为按对象去重，并用 `rowspan` 推出真实节次跨度（跨第1-2节而不是两个 1-1 / 2-2） |
| **格子内容不能按行喂给解析引擎** | 格子是字段堆叠、没有星期，引擎会按「缺少星期」把每行都丢掉（一门都解析不出）；逐行喂又会让「张老师」变成一门课。改为先分类再合成一行带 `地点:`/`教师:` 显式标注的文本 |
| **`东区一教101` 认不出是地点** | 原启发式的关键词里没有「教」，而「教」单独加进去会把「教育学」误判成地点；改成「教 + 房间号」才成立（`东区一教101` 命中、`教育学` 不命中） |

## 八、v0.5 补齐「课程表分享图片」（P2）

传播入口是这类产品最实际的增长点：用户把课表发到班级群、朋友圈，图里就带着产品名。
**截图不解决问题** —— 会带上地址栏和工具栏、尺寸随窗口变、发到群里可读性完全看对方手机。

| # | 决策 | 理由 |
| --- | --- | --- |
| 1 | **固定 1080×1446（3:4 竖图）+ 按数据重排版式**，而不是截当前视图 | 尺寸稳定、时间列带真实起止时间、页脚能补充「另有 N 门不在本周」这类截图给不出的信息 |
| 2 | **分三层：布局（纯函数）→ 绘制（只执行指令）→ 浏览器胶水** | 「布局算得对不对」和「canvas 能不能用」必须能分开定位，揉在一起出偏差就分不清是算错还是画错 |
| 3 | 文字宽度用**依赖注入**（`measure(text, size)`） | 布局要保纯函数，而量宽度必须问浏览器；Node 测试注入确定性估算函数，真机走 `measureText` |
| 4 | 同一天撞车的课**分泳道并排**，不缩成一坨 | 与屏幕上周视图一致；一个泳道里再多了才纵向堆叠 |
| 5 | 课名放不下时**折行 + 降一档字号**，最后才截断 | 单列可用宽度只有 ~89px，19px 字下就 4 个汉字 —— 直接截断会把「数据结构与算法分析」变成「数据结…」，等于没写 |
| 6 | 深色图**独立于页面主题**决定配色 | 浅色页面里选「深色导出」时，若沿用当前主题的 CSS 变量就会白底浅字。深色主题下课块底色转 HSL 压暗到固定亮度（保留色相） |

### 这一轮真正踩到的坑

| 现象 | 根因 | 现在怎么防 |
| --- | --- | --- |
| 图上印出「1-16 **周周**」 | `CF.weeksText()` 返回的文案本身已带「周」，又补了一个 | 屏幕上不显示这段文字，只有导出图才看得见 → 断言禁止文案含「周周」 |
| **深色图里课名整片看不见** | 课块底色取的是「当前页面主题」的 CSS 变量；浅色页面导深色图时底色仍是浅色，而深色主题的文字色是近白色 | 课块底色按主题压暗 + 亮度差断言（≥110）+ 真机**数像素**检查。此前的结构性检查全过：尺寸对、指令合法、PNG 完整 |
| 页脚写「共 2 门课程」但图上只有 1 块 | 「节次超出当前作息的课」被算进了 `visible`，只是后面画不出来 | 断言「页脚门数 == 图上课块数」。这是**变异测试**抓出来的假护栏（只断言课块内容时该变异全绿） |
| 单文件版残留坏 `<link rel="icon">` | 三处 `replace` 漏 `g` 标志，只删了第一个匹配 | 补 `gm` + 构建期自检改扫全部 `<link>`/`<script>` |
| 打包体积低估 18% | 用 `out.length`（UTF-16 码元）算体积 | 改 `Buffer.byteLength(out, 'utf-8')` |


## 九、v0.5 补齐「桌面小组件 / 常驻提醒」（P2）

对标 ClassIsland / sleepy / 拾光课程表 的「常驻大屏、一眼看到下一节课」能力。
做成 **托盘常驻 + 无边框角落挂件**：托盘提示直接写「下一次课是什么、还有多久」，
挂件显示下节课的课名 / 时间 / 地点与**秒级倒计时**。关掉主窗口不退出应用，
点托盘图标即可唤回。关键不在「画一块 UI」，而在**把网页和托盘的判定钉成同一份真相**。

| # | 决策 | 理由 |
| --- | --- | --- |
| 1 | **主进程 `require` 网页侧的 `core.js` / `remind.js`（UMD），托盘 / 菜单 / 挂件三处共用同一份判定，不复制逻辑** | 复制一份只会改一边忘一边，最终出现「托盘说 8:00、窗口说 8:05」的自相矛盾 |
| 2 | **主进程只在内存持有课表快照（启动时由主窗口推一次），不落盘** | 课表真正的持久化归 `localStorage`；主进程再存一份就是两份真相，用户删学期后会残留旧数据 |
| 3 | **显式 `phase` 状态机**（`nodata / beforeterm / afterterm / off / current / next / missing / none`） | 「没开学」「已结课」「放假」「作息缺失」都会表现为「没有下一节课」，靠一串 if 顺序区分迟早漏一种，而它们的成因和用户该做的事完全不同 |
| 4 | **item 必须带精确的 `startAt` / `endAt`（epoch ms），渲染层不用「距现在 N 分钟」反推** | `startsInMin` 取整到分钟，反推出来的上课时刻最多偏 30 秒，而最后十分钟要显示到秒，正好错在最在意的窗口里 |
| 5 | **窗口位置必须夹回可见区**（重叠区 ≥ 48px 才算「看得见」） | 挂件无任务栏、无标题栏，位置一旦存到已拔掉的外接屏坐标，用户既看不到也抓不回，只能手删配置 |
| 6 | **跨天称呼判据 `(weekdayOf(now)+daysAhead) <= 7` 才说「本周X」，前缀只加「本/下」** | 同分享图的「1-16 周周」同源坑：前缀与 `DAY_NAMES` 都带「周」会拼出「下周周三」 |

### 这一轮真正踩到的坑

| 现象 | 根因 | 现在怎么防 |
| --- | --- | --- |
| 托盘提示与挂件窗口「下一次课」对不上 | 两套各自算一遍 | 三处都走 `widget-store.js` 的同一份 `buildView()`，view-model 是纯 JSON 跨 IPC 传递 |
| 一句话「马上**上** 高等数学」 | `startsInMin<=0` 时拼出「马上」+「上 」+ 课名 | 改为「马上上课：课名」 |
| 挂件说「下周周三」 | 前缀「下周」再拼 `DAY_NAMES`=「周三」 | 前缀只加「本/下」，断言禁止文案含「周周」 |
| 未开学 / 学期结束都落进「接下来 14 天没有课」 | 丢掉了关键阶段信息 | 引入显式 `phase`，`beforeterm` 给「距开学还有 N 天」、`afterterm` 给「学期已结束」 |
| 安全模式截图整块不透明、墨量 100% | `--disable-gpu` 下透明窗口不保留 alpha，是环境特性非缺陷 | 像素判据改用「墨量 2%~45% + 明暗像素双存在」，不再断言卡片外缘透明 |
| 自检第 7 节超时、应用整体退出 | 在小组件 CDP 连接上调了 `Browser.close`（浏览器级命令，关掉整个应用） | 只 `ws.close()` 断开这一个连接 |
| 倒计时在最后十分钟「整点跳变」或偏 30 秒 | 渲染层用取整数反推锚点 | 视图直接给 `startAt`/`endAt`，渲染层 `anchorsOf` 直接用它 |

## 七、v0.5 依据移动端竞品补齐的缺口：上课提醒 + 调休感知

本轮把对标范围从「开源课表项目」扩到**移动端商业课表**（超级课程表 / 课程格子 / WakeUp / 小爱课程表 / 时课 等），
结论很一致：**「课前提醒」是这类产品的第一功能**，而 CourseForge 之前只是把提醒写进导出的 `.ics`
—— 等于要求用户额外装一个日历 App 才能被提醒到，**等于没有提醒**。这是定位层面最大的缺口，先补。

| # | 缺口 | 竞品对标 | 落地情况 |
| --- | --- | --- | --- |
| 1 | **课前提醒** | 超级课程表 / WakeUp / 小爱课程表 / Class Widgets 均有 | 网页端与桌面端共用同一套判定引擎（`web/js/remind.js`，纯函数）；可设「上课时 / 5 / 10 / 15 / 20 / 30 分钟前」；默认**关闭**，因为通知授权只能由用户点击触发，默认开着只会让人以为坏了 |
| 2 | **调休感知** | 竞品普遍做得不够好 | 放假当天不提醒；**调休补课的周末照常提醒**。数据不联网，由用户在「今天」面板上一键标记（`settings.days`）——联网拉节假日表需要外部接口与长期维护，与「零依赖 / 数据自己在手里」冲突 |

### 为什么提醒引擎写成纯函数

提醒类 bug **全部藏在边界上**：跨天、跨周、单双周、调休、页面休眠后恢复、同一节课重复弹。
这些场景手点是点不到的（要等到那个时刻），所以判定必须能被「喂一个时刻」直接测：
`runTick(课程, 设置, 此刻)` → 该弹什么。测试里把时钟当参数传，30 秒能跑完现实中一个月的边界。

### 调休只做「本地标记」的取舍

不联网取节假日表（例如第三方万年历接口）的原因：
1. 需要引入网络依赖与缓存失效处理，破坏零依赖；
2. 各校调休安排与法定假日**并不一致**（周末补课、周中放假都常见），外部表反而更不准；
3. 用户自己最清楚自己学校怎么调，标记一次的成本远低于维护一张全年的表。

## 八、明确的取舍（不做什么）

- **不做账号体系**：学生课表是私事，导出/导入 JSON 已够迁移，多一个账号就多一份泄露面。
- **不做云同步为默认**：与「数据在自己手里」的定位冲突，只作为 v1.0 的可选能力。
- **不做原生 App**：三端复用一份零依赖网页的收益远大于原生性能收益；PWA 已能覆盖「添加到主屏幕」的需求。
- **不做大文件/视频存储**：超出课表工具的边界。
- **不引任何前端框架**：一旦引入，单文件离线版就不复存在，这是本项目最核心的差异点。
- **不保存教务系统账号密码（明文）**：v0.5 起提供「记住账号」选项，但**默认不勾选**，且只能走系统凭据加密（Windows DPAPI / macOS Keychain / Linux keyring）；系统不支持加密时**直接拒绝保存**，绝不降级为明文。密码只经过一次 IPC，不写日志、不落盘明文，随时可「忘记账号」一键清除。理由：把「每次手输一长串密码」的成本降到零，同时把泄露面控制在「本机当前用户」这一层 —— 解锁过这台机器的人本来就什么都拿得到，多存一份加密凭据并不额外增加实质风险。

## 十、v0.5 补齐「考试倒计时与自定义事件」（P3）

对标 ClassIsland 的「考试倒计时」。竞品普遍把考试做成独立大组件，
我们按自己的克制路线做轻：事件就是**一条带日期的备注**，不搞倒计时大屏。

| 设计决策 | 理由 |
| --- | --- |
| 事件挂在**学期**上，不开独立存储 | 学期是「一阶段生活」的天然容器：切学期、删学期、导出备份、JSON 迁移全都自动带上事件；单独存储则每条数据通路都要多判一层「这是哪个学期的事件」 |
| schema 仍是 v2，events 是可选字段 | 旧数据缺 events 就当空数组，零迁移成本；升 v3 会逼所有旧备份走一次升级，收益为零 |
| 清洗时**丢弃**坏项而不是报错 | 事件是用户手填的自由文本，坏输入是常态；`normalizeEvent` 返回 null 让调用方安静丢掉，配合添加入口的即时校验，不让一条坏数据把整个列表搞挂 |
| 倒计时文案在 `upcomingEvents` 里**定稿**（countdownText） | 首页 chip、托盘提示、挂件三处共用同一份文案 —— 分头算迟早出现「托盘说明天、挂件说还有 1 天」的自相矛盾（同 widget 的教训） |
| 挂件只显示**第一条**事件 | foot 只有一行位置；罗列是首页的事，挂件只回答「最近要防着哪一件」 |
| 托盘只上 **7 天内的考试**，普通事件不上 | 托盘空间是拿来防「最硬的 deadline」的；截止日这类自己记的事挂上去只会稀释注意力，两行状态 + 一行考试是上限 |
| 事件不因放假 / 学期结束被吞 | 「暑假里还挂着 8 月底的驾照考试」是合理诉求；课程状态机（phase）管上课，事件是另一条时间线，互不劫持 |
| 考完试自动消失（过去即滤除） | 倒计时工具最怕过期信息赖着不走；不设「手动归档」—— 需要留记录的人早该用日历导出 |
| 考试提醒**不依赖上课提醒开关** | 「我不想每节课都被提醒」和「下周的考试别忘了我还是想知道的」是两件事；两者只共用 deliverAlert 这一层皮 |
| 去重账本单独存 localStorage（`wb_courseforge_exam_notified`） | 账本是「今天提过没有」的一次性记录，跟着备份/导出走只会把 A 机器的旧账带去 B 机器；账本每天自净，只留当天的键 |
| 7 天内**每天每条**弹一次（不是只弹一次） | 只弹一次的话，用户在上课时随手划掉通知就永远失去了这条提醒；「每天一次」把「忽略」的代价降到一天 |
| 添加考试后**立刻**跑一轮提醒检查 | 用户刚录入手边的考试，最想要的反馈就是「这门考试 X 天后」——比干巴巴的「已添加」更有信息量；不用等 30 秒的定时 tick |

踩到的坑：

| 坑 | 教训 |
| --- | --- |
| 时间校验用 `^\d{1,2}:\d{2}$`，`25:00` 直接放行 | 正则只验形状不验范围；顺带把合法时间**零填充**成 HH:MM，字符串比较才与数值同序，「同一天按时间先后排」才不会把 9:00 排到 10:00 后面 |
| 变异锚点单写一行 for 循环命中了别处同款循环（见第九节） | 这次写新变异时全部带上唯一上下文，5 条一次全红 |

## 十一、v1.0 补齐「WebDAV 云同步」（可选，默认仍全本地）

竞品的云同步普遍要注册账号、数据过第三方服务器 —— 那与「数据在用户手里」直接冲突。
方案是**用户自备 WebDAV 服务器**（坚果云 / Nextcloud / 群晖都行），CourseForge 只当一个老实的手推车。

| 设计决策 | 理由 |
| --- | --- |
| **可选项，默认关闭** | 不填服务器配置，这个功能就不存在；「数据默认只在本地」不能被任何新功能稀释 |
| v1 只做**手动两键**（上传/恢复），不做自动同步 | 课表是低频变更数据，自动同步的冲突处理复杂度远超收益；「覆盖云端 / 覆盖本机」语义清楚、各自有确认 |
| 备份格式**复用现有 JSON 导出**，云端固定一个文件 | `CourseForge/courseforge-workspace.json`，与「导出备份」是同一份结构（单一真相源 `backupPayload()`）；不搞云端版本历史 —— 历史靠本地导出的时间戳文件名 |
| **传输层注入**（webdav.js 纯逻辑，不碰 HTTP） | 配置清洗/路径/载荷安检/认证头全是纯函数，HTTP 由调用方注入：桌面端传 Node 实现、网页端传 fetch —— 全部逻辑离线可测，与 remind.js 同一哲学 |
| 桌面端**主进程代发 HTTP**，网页端 fetch 尽力而为 | 用户自备的 WebDAV 服务器十有八九不开 CORS；主进程没有跨域限制，是云同步的正门。网页端被拦时明说「请用桌面版」，不静默失败 |
| 密码**只存密文**（safeStorage/DPAPI），与教务账号同套铁律 | 凭据文件独立（`webdav-credentials.json`）—— 清教务账号不能连坐清掉 WebDAV 密码；用存储密码前必须校验**用户名一致**，防止换账号拿旧密码去撞 |
| 网页端「记住密码」= **明文本机存储**，勾选即告知 | 桌面端有能力加密就加密；网页端没有 DPAPI，与其假装安全不如把取舍摆到勾选框上 |
| 云端取回的备份**先安检再进工作区** | 服务器返回什么都有可能：结构不对、版本不认识、超过 20MB 一律挡下；恢复前用 confirm 列出「云端 N 学期/M 门课 · 备份时间」与当前本机对比 |
| 自研 WebDAV 客户端，不引第三方库 | 协议只用到 PUT/GET + Basic 认证 + 跟随 3xx（最多 3 次）+ 30 秒超时 + 10MB 响应上限；一个库的依赖面远大于这五个需求（零运行时依赖是硬约束） |

## 十二、v1.1 补齐「检查更新」（桌面端自动更新的最小可靠版）

竞品普遍带自动更新，但代价各不相同：electron-updater 是额外依赖 + 静默下载安装 ——
在安装包**未签名**的现状下，Windows SmartScreen 会拦静默启动的安装器，自动化反而制造工单。
方案取最小可靠面：

| 设计决策 | 理由 |
| --- | --- |
| **自研「检查更新」，不引 electron-updater** | 零运行时依赖是硬约束；且静默下载安装 exe 在未签名现状下必被 SmartScreen 拦，体验更差 |
| 只查版本 + 给下载链接，**不自动下载安装** | 用户自己决定何时升级；链接只接受 github.com 域 —— API 返回的 `html_url` 不盲信，白名单外一律回落到固定 releases 页 |
| 版本源 = GitHub Releases `releases/latest` | 不需要自建更新服务器；404（还没有发布过版本）是**预期态**，明说而不是报错 |
| 版本比较手写 semver 三段比较 | 只需 major/minor/patch 数字比；解析失败给结构化错误，不当「已是最新」糊弄用户 |
| 网页版不提供检查更新 | 网页刷新即最新；该区按桌面桥判空隐藏（与桌面小组件开关同一套逻辑） |
| HTTP 细节同 WebDAV 客户端（30s 超时、响应上限、注入可测） | GitHub API 缺 User-Agent 头直接 403；测试起本地真服务器，不桩测桩 |

### 发布闭环

检查更新要有意义，仓库里必须真的存在 release。本轮同时完成首次发布：
版本 bump 到 **0.2.0** → CI 绿后重打包 → 创建 GitHub Release `v0.2.0` 并上传安装包资产。
这样老安装包（0.1.0）点「检查更新」就能看到 v0.2.0 —— 功能当场端到端可验证。
